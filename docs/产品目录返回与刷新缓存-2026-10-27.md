# 产品目录返回与刷新加载

原因：PublicCatalogProvider 每次 pathname 改变都 force + foreground 重读完整目录，先把 ready 产品清空为 loading；此前已完成的列表缩略图离开页面也会立即释放。实测 RPC 约 620–1084ms，卡片每次重新等待它完成。

修改：
- 保留 Provider 内已验证的目录，路由切换不再清空；15 秒内事件合并复用，之后后台读取替换。
- sessionStorage 仅保存公开投影，按后台 URL/公开 key 隔离，30 秒过期；刷新可先显示短期目录，始终发起后台更新。缓存不延期到读取时，写入以成功网络读取为准。
- 网络失败或超时立即清除产品和标签页缓存；新响应中下架的产品立即移除。没有改变 RPC/RLS 或公开资格判断。首次访问、缓存过期仍需等待实际网络响应。
- 列表清晰缩略图在原有内存池保留 30 秒；原有 4MB 闲置图片上限继续生效。

验证：
- TypeScript、完整单元测试与生产构建通过；新增过期、后台隔离、清除、复用窗口测试。
- tests/publicListNavigation.mjs 用 1.8 秒延迟的隔离 RPC 验证详情返回无额外目录请求、刷新先呈现、下架移除、失败清除；不写生产数据。
- 本地真实接口：首次 1517ms，详情返回 48ms（额外目录请求 0），刷新 840ms。开发服务器含模块加载开销；这些数值不是所有网络条件下的保证。
