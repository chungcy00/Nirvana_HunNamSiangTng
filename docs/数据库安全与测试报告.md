## 维护与复测

已部署的八份 SQL 由 `supabase/deployment-manifest.json` 列明。`catalog_private_boundary` 迁移通过 authenticator 的 `pgrst.db_schemas` 将暴露范围固定为 `api`，覆盖 Dashboard 的 Exposed schemas 设置；后续用 SQL 维护。若需恢复 Dashboard 管理，先审查暴露范围，再重置该角色配置并重载。

云端连接工具生成的迁移版本与本地文件名不同，见 `supabase/deployment-manifest.json`。后续 CLI 部署必须先核对历史，不得直接重复推送或重置远端。

本地安装根目录依赖并启动 Docker Desktop 后运行：

```sh
npm ci --prefix supabase/tests
npm run catalog:security:start
npm run catalog:security:test
```

启动程序仅管理独立测试栈，网关及数据库限定 127.0.0.1；首次初始化只应用部署清单里的迁移，工作区其他待审迁移不会被自动执行，已有数据库不自动重置。集成测试拒绝远端地址，会创建本地测试用户、产品及文件。生成密钥保存在被忽略的 `work/catalog-security`，不得提交。本地测试数据会保留在独立测试栈，不能当作正式产品。

测试证据：`supabase/tests/integration-result.json`、`cloud-http-result.json`、`hosted-verification-result.json`；可重跑的 SQL 为 `schema-contract.sql`、`hosted-draft-validation.sql` 和 `hosted-conflict-validation.sql`。`cloud-http.mjs` 仅需公开密钥即可复测云端 HTTP 边界。管理员维护脚本在 `scripts/catalog-security/bootstrap-member.mjs`，无网页自助提权入口。可选远端命令行预检读取本地 `.env.local`；本次云端迁移与 SQL 复测通过已连接 Supabase 工具完成。

冲突修复依据：[Supabase 关于 RPC 使用 40001 导致无限重试的说明](https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b)。本阶段完成数据库及安全边界；产品复制及文件补偿编排、后台页面、真人密码登录、前台数据库接入仍属于后续整合验收。
