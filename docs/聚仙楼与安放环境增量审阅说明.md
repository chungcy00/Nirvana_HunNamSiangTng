## 增量文件

`supabase/migrations/20261021171754_niche_placement_type.sql`：

- 仅给 `private.niche_details` 增加可空、无默认值的 `placement_type text`；CHECK 只允许 SQL NULL、`indoor`、`outdoor`，空字符串也不接受。无数据回填。
- 替换 `private.assert_product`，保留原规则，仅新增骨灰位发布必填检查；其他类别规则不变。
- 替换 `private.public_product`，阻止环境缺失的骨灰位进入公开读取及普通图片公开访问。当前云端无已发布骨灰位，因此没有现存公开条目的兼容问题；若执行前情况变化，应先复查。
- 替换公开列表函数，骨灰位返回 `placement_type`。现有详情函数会在 `attributes` 内返回新增字段，无须改写。
- 现有保存函数通过真实字段元数据识别 `niche_details` 新字段；后台读取自动返回该字段，无须复制重写保存及身份验证代码。
- 保留函数所有者、RLS、角色授权、审计、原子保存和乐观锁。不增加公开原表权限、筛选、朝向、面积、楼层、层位或价格分级。

前端在 `src/types/index.ts` 增加可选骨灰位资料；`src/catalog/nichePlacement.ts` 处理 API 映射、标签及保存载荷；卡片和详情显示明确填入的“室内／室外”标签，并保留“RM ××× 起”。空值不显示标签，不按名称推断。

`src/components/NichePlacementField.tsx` 提供骨灰位专用单选字段，草稿可清空，发布时必选，其他类别不显示。字段是为后台编辑表单准备的组件；当前项目没有完整后台编辑页面，所以本次没有新增后台路由、登录界面或完整保存页面，也没有把前台静态目录接到云端。数据库 RPC 保存流程将在确认后验证，界面端到端保存仍需宿主编辑页面接入。
