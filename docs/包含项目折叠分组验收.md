# 包含项目折叠分组验收

日期：2026-10-23（Asia/Kuching）。按用户确认实现：“包含项目”总标题不变，子标题以折叠方式打开对应明细。用户明确同意新增可空的分组字段，不自动调整现有产品资料。

## 实现

- 原表 private.product_inclusions 新增 group_title，可空、无默认值，非空标题最多120字；不新建表，不修改明细名称或内容。
- 公开详情 RPC 附带该字段，继续使用原公开条件、宗教隔离及排序；函数所有者、执行权限与 search_path 均保留。
- 前台：有分组时使用原生 details/summary，默认收起，鼠标、Enter和Space可展开／收起。子标题下显示明细；未分组旧资料保持普通列表。
- 后台：添加子标题、添加本组明细、改名、清空标题、移动整个分组、组内明细排序和删除明细；预览同步折叠展示。表单仍受原只读／忙碌状态限制。移动明细后保留展开状态。
- 两端复用同一分组规则：按小标题首次出现的顺序排组，组内沿用项目顺序。宗教与方案关联、数量、单位、说明继续保留。
- 殡仪仍完全无照片；字体、配色、卡片与其他页面布局不变。

## 验证

- 前台102项、后台15项自动测试通过；两端类型检查和构建通过。
- 独立本地真实Postgres的8组检查通过：管理员RPC保存与回读、草稿匿名不可见、非法标题原子拒绝、改名／清空／排序、发布后公开读取与宗教隔离、复制保留分组、匿名写入拒绝、隐藏后公开资料消失。
- 本地测试所有DDL、身份、产品和审计均处于事务内并回滚，没有写入云端测试产品。
- 独立浏览器预览检查了前台鼠标与键盘折叠、后台编辑及两级排序。前后台390px手机宽度均无横向溢出，桌面效果已保存。
- 云端迁移版本20261023141149，名称inclusion_group_titles；本地文件由CLI生成，映射已写入deployment-manifest。
- 云端核对20产品、267包含项目：原字段数量与逐行摘要均不变，所有新分组值为NULL。18表RLS、公开函数所有者和权限保持原样，见配套JSON。
- 安全Advisor未增加问题；仅保留迁移前已有的泄露密码保护未启用提示，未变更Auth配置。

## 使用与限制

现有产品没有自动填写分组。管理员需在“包含项目”中添加或填写子标题，把明细放入对应组并保存；正式公开资料更新后，前台才会出现相应折叠区。本次不推断原有267条明细的分组，不发布或修改现有产品。
