## 本阶段实现

沿用第一阶段后台，加入真实密码恢复与邀请接收入口。保留 Supabase PKCE 回调，并增加“粘贴邮件链接验证”：使用官方 token hash 验证接口，解决跨浏览器缺少原始 PKCE 凭据的问题。两种入口均验证 `getUser` 与 `current_catalog_member` 后才展示设置密码表单，再退出并重新登录。兼容现有邀请的 implicit 回调，不导入演示身份。回调会清除网址中的 code／token，不接受外部 `next` 地址；后台设置 `no-referrer`。

登录会话恢复、刷新、退出均调用真实 Auth。异步成员查询按最新请求结果生效，防止旧查询覆盖新会话角色。普通用户的 `user_metadata.role` 不参与权限决策；成员角色及停用状态每次由数据库验证。后台没有公开注册入口，云端也关闭了公开注册；Email 登录保持开启，匿名登录保持关闭。

为本人验收临时启用 `VITE_AUTH_VERIFICATION_ONLY=true`，连接现有云端，只读取身份、角色、产品总数及参考资料。该模式没有产品编辑／发布按钮，也没有配置云端高权限密钥。正常后台构建保持该开关为 false。
