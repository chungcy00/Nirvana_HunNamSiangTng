# 图片与产品加载优化

日期：2026-10-27。

## 原因与修改

- 产品页面原来先请求列表，再对每件产品请求详情。现改为一次 `catalog_product_snapshot`，沿用 `fg_catalog_reader` 与现有 RLS，并核对返回数据与旧详情投影完全一致。保留每次重新验证公开状态、错误时清空数据的行为。
- 实景与设计图片的内嵌位置、隐藏大图弹窗原来分别下载完整原图。线上样本有两张约 9 MB 的照片，页面合计传输约 43 MB。
- 新增前后台共用的图片预览接口，按显示尺寸生成 160/480/960/1920 像素 WebP，保持比例与原色；原图文件和业务资料保持不变。图片接近可见区域时才下载，大图弹窗打开后才加载；同一权限身份、同一图片及尺寸在挂载期间共用下载。
- 每次图片预览请求，包括服务进程内的缩放结果缓存命中，都先以调用者身份向 Storage 发起 HEAD 权限检查；不使用 service role、公开桶或签名链接。版本标识变化时重新生成预览；响应 `private, no-store`。进程缓存仅保存缩放数据，限制 16 MB / 48 项。
- 后台首屏和切换筛选不再额外等待 200 ms，只有输入搜索文字保留防抖；过期列表请求会取消。首次登录避免重复验证同一初始会话。
- 数据服务位于首尔（ap-northeast-2），函数部署明确设为同一区域 icn1，避免图片处理跨洲读取原图。
- 本地 Vite 与线上 API 均提供相同图片预览服务；旧部署与本地服务不可用时，可回退到原有权限控制的原图读取。

## 验证

- 当前三件公开产品的新投影与旧详情投影逐项完全相同；新增函数归受限 reader 所有，并撤销临时 schema CREATE 权限与 PUBLIC 执行权限。
- 141 项前台/共享测试、26 项后台测试，前后台类型检查与构建。
- 实际线上图片经本地同一预览服务测试，三张内嵌图合计约 171 KB，对比原先约 43 MB，降低约 99.6%。产品读取从四个 RPC 降至一个。耗时会随网络和冷启动变化。
- 后台隔离浏览器测试确认产品表使用 160 像素缩略图，预览复用图片资源，关闭的大图弹窗不下载图片，打开后正常显示；没有写入正式业务资料。
- 自动测试覆盖原色、尺寸、缓存命中仍检查权限、权限撤回后的拒绝、新版本重新生成、不合法路径与尺寸拒绝、共享下载与最后释放取消。

线上首轮复测确认：三张内嵌图合计 171,770 字节，产品详情可见时间约 1.2 秒（该次网络样本），缩略图接口返回 image/webp 和 private, no-store。

## 后续修正：提前保存预览图

用户反馈仍慢后，确认前一轮仅缩小了浏览器传输量，进程冷启动时仍需读取原图并缩放。

- 建立私有预览桶，读取权限实时关联原图公开状态、宗教范围和后台成员权限，禁止签名链接及覆盖。
- 8 张已关联照片的 32 份预览已全部补齐。原有 14 个原图对象、20 件产品和 8 条图片关联保持不变。
- 前后台优先直接读取已保存的 WebP，不经过临时缩放；只有缺少预览时才回退。新上传、替换和复制会生成预览，清理原图时同步清理预览。
- 后台短期返回列表在内存中复用图片 30 秒，按会话隔离并限制闲置内存；公开前台仍保持卸载即释放。
- 已修正线上 Node ESM 相对模块路径，并完成编译后服务启动检查。
- 144 项前台/共享测试、26 项后台测试及前后台构建通过。线上浏览器确认内嵌图和大图都直接读取预览，没有原图或缩放函数请求。后台隔离浏览器确认进入编辑再返回列表不重复下载缩略图。
- 160 像素缩略图连续读取样本为 997/512/444 ms，每张 3,718 字节；网络与首次请求仍会影响等待时间。

## 后续修正：照片随产品资料首次显示

- 进一步测量发现，已保存的预览仍需在产品 RPC 后单独等待约 0.4–1.2 秒；高分辨率屏幕主图约 400 KB。仅缩小文件不能消除这段空白。
- 增加私有衍生预览表，160 像素 WebP 以受限制的数据 URI 随已有的授权产品 RPC 返回，列表、编辑页、公开详情及后台 iframe 先显示小图，原有图片链路异步替换为清晰图。没有缓存整个公开目录，也没有更改产品公开状态验证。
- 预览表读权限关联原图权限，写入仅授权成员或服务端使用；匿名不能直接读表或写入预览。上传、复制、清理同步处理此衍生数据，保存表单时排除衍生字段。
- 145 项前台/共享测试、26 项后台测试及双端构建通过；后台隔离浏览器将 Storage 请求延迟 2.5 秒，验证缩略图与 iframe 在请求完成前已经显示，并验证之后升级为清晰图。
- 8 张照片的小预览已补齐。随后针对用户要求，详情页改为进入时预载全部照片的 1920 像素清晰版本，主图、缩略图、设计图和放大图共享同一次下载；列表仍按小尺寸读取。产品详情卸载即释放其持有资源，公开状态仍在新页面读取时重新验证。
- 修正自定义 API schema 的服务端角色访问和受限 RPC 角色的预览谓词权限；服务身份判断封装于不向浏览器授权的函数，无需扩大 writer 对 auth schema 的访问。
- 实际页面将图片网络请求额外延迟 3 秒后，本地和线上照片分别在产品详情出现后约 17 / 24 ms 显示小预览；清晰图随后正常替换。此数字为当次网络样本，不代表整个页面总加载时间。
- 146 项前台/共享测试、26 项后台测试及双端构建通过。本地浏览器确认 Zone AA 全部 5 张清晰图在点击前预载，反复切换及开关大图后仍只有 5 次图片请求；开发模式的 React effect 重放也不会取消并重下整批照片。

## 上传等待与进度展示

- 原来先上传原图，再逐一上传四份预览，最后才把照片加入编辑卡片，导致选中文件后长时间没有反馈。
- 根据后续反馈，改为已有图片卡片后的紧凑进度条，移除临时大卡片。原图上传使用调用者会话与同一 Storage 权限，通过 XHR 上传字节事件显示真实百分比；发送完成但服务端未确认时单独提示确认阶段，随后显示四份预览的实际完成数量。四份预览保持并行处理。
- 整个文件处理完成才把正式卡片追加到已有卡片末尾；多文件保持选择顺序，替换文件保留原卡片位置。照片文件不额外压缩或改变原色。
- 浏览器回归脚本 `apps/admin/tests/upload-instant.mjs` 阻塞原图上传，验证进度条位于已有卡片之后且高度紧凑、字节事件更新为 50%、预览并行、失败时保留已有照片，以及追加和替换的位置稳定。所有数据与文件请求均为隔离响应，没有写入线上产品。线上 Storage 的 CORS 预检已验证允许所需请求头。
