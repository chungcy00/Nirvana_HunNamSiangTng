# 静态缓存与产品刷新优化

2026-10-23。仅实施用户确认的两项优化；图片文件、卡片、字体、配色、CSS 和动效未修改。

## 实施范围

- 仅为 `/assets/` 下带至少八位哈希的 JS／CSS 设置 `public, max-age=31536000, immutable`。HTML、固定文件名图片、Supabase 产品接口及后台未加入长期缓存规则。
- 首次读取、失败重试仍显示既有加载状态。页面路由切换仍保留前台发布核验，不直接以旧结果填充新详情。
- 已成功载入时，定时／可见性刷新在后台进行；刷新成功直接替换结果，不插入加载面板。失败或 20 秒超时均清空旧产品，显示原失败与重试界面。
- 保留 60 秒刷新、焦点／可见性检查。正在进行的请求合并，自动触发的短时重复事件在一秒内去重；手动重试及路由核验可绕过该间隔。
- 不修改数据库、正式产品、发布条件、图片权限或 API 的 `no-store` 策略。

## 验证

- 84 项前台测试、类型检查与生产构建通过。新增测试覆盖后台刷新不清空已验证资料、重复事件合并、失败清空、手动重试、超时、卸载取消、路由核验以及缓存匹配边界。
- 独立本地 HTTP fixture 配合实际 PublicCatalogProvider 和实际页面测试，不连接正式 Supabase：组合刷新只增加一次目录请求；三秒成功刷新期间卡片移除次数 0、加载面板插入次数 0；模拟 503 后旧卡片数变为 0；恢复服务后真实重试按钮恢复列表；返回空列表后旧产品不残留。
- 生产 CSS 产物仍为 `index-DvXrRKQF.css`，与修改前完全相同。
- 线上已确认：新 JS 与既有 CSS 均返回一年 immutable 缓存；/nirvana、/contact、标志图片及排序图标仍返回 max-age=0, must-revalidate，没有扩大缓存范围。六条响应均 HTTP 200。详见同目录《缓存与刷新线上响应头.json》。未进行模拟 4G、真机 LCP 或 CLS 测试，不将缓存规则修改宣称为首屏速度达标。

本地可重复验证：启动 `tests/refresh-fixture-server.mjs`；使用独立 Vite 端口 3006，设置测试 URL 为 `http://127.0.0.1:3026`、测试 publishable key 为 `sb_publishable_refresh_fixture`；打开 `tests/refresh-browser.html`。这些 fixture 不进入生产构建，不包含实际密钥或正式资料。
