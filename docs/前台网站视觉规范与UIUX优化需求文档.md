# 富贵山庄｜前台网站视觉规范与 UI/UX 优化需求文档

**版本：** v1.2（基于 v1.1 补充产品导航与筛选 UI 规范，锁定现有字体）  
**修订日期：** 2026-10-22  
**适用范围：** 现有消费者前台网站：首页、富贵山庄产品目录与分类、产品详情、联系页及现有云南善堂介绍页面；桌面与移动端  
**不适用范围：** 黑白灰后台管理 UI、Supabase 数据库结构、产品发布权限与业务规则  
**部署规划：** 前台 Cloudflare Pages；后台 Vercel（部署迁移本身不属于本 UI/UX 文档）

> **实施优先规则**：本文件仅规范前台视觉与易用性。任何与已确认的四份富贵山庄产品系统需求文档、既有联系表单／问卷流程发生冲突的要求，均不得据此改变原规则；应先标记冲突并停止该项修改。本文档不授权增加新业务功能或变更数据库。

---

## 0. 背景、目标与实施边界

网站现有页面、导航与产品资料结构应予保留。本轮优化聚焦：

1. 用一组可维护的 **Design Tokens** 统一颜色、间距、边框及组件状态（保留现有字体），避免一次性色值分散。
2. 在**不改变页面信息架构**的前提下，统一按钮、卡片、价格呈现样式、图片占位、表单反馈及图标。
3. 改进桌面和移动端的阅读、触控、横向滚动提示、键盘操作及性能。
4. 核实当前 GitHub 源代码与正在部署的前台页面是否一致；这是待验证事项，而非已确认故障。

**明确不做：** 不重新规划七大产品类别；不增设热门配套、分期付款、相关产品推荐、额外 FAQ 或云南善堂产品分类；不强制所有卡片增加咨询按钮；不改变问卷和联系表单既有提交行为；不强制全站常驻 WhatsApp 浮动按钮；不重新制作后台 UI。

## 1. 视觉设计原则

| 原则 | 执行规则 |
|---|---|
| 克制温柔 | 留白与可读性优先，避免强促销表现 |
| 庄重可信 | 价格、说明、服务内容清楚，不制造未经证实的保证 |
| 视觉宗教中立 | 通用区块避免偏向特定宗教；宗教专属产品图片和标签按真实资料展示 |
| 操作清晰 | 沿用现有咨询、详情与返回路径；改善可见性，不随意增加重复入口 |
| 金色克制 | 哑光金仅用于少量强调，不能以装饰盖过正文和价格信息 |

## 2. Design Tokens 与视觉基础

### 2.1 色彩

沿用原版已提出的**黛绿 × 哑光金**方向。以下为前台建议 Token；实施时应先核对现有品牌视觉与 CSS，确认后统一替换，不影响后台黑白主题。

| Token | 值 | 用途 |
|---|---|---|
| `--primary` | `#2E4638` | 前台主按钮、重点标题、导航激活 |
| `--primary-hover` | `#3D5A49` | 主色交互状态 |
| `--accent` | `#B08D46` | 少量视觉强调；不强制全部价格使用金色 |
| `--accent-soft` | `#F0E8D8` | 浅强调底色 |
| `--support` | `#8A9A8B` | 次级图标与辅助信息 |
| `--bg` | `#F7F3EA` | 前台页面背景 |
| `--surface` | `#FFFFFF` | 内容卡片及表单 |
| `--surface-tint` | `#EFF2E9` | 柔和替代背景／图片占位 |
| `--text` | `#20261F` | 正文 |
| `--text-muted` | `#626B65` | 次要文字 |
| `--line` | `#E4E2D9` | 边框与分隔线 |
| `--success` | `#3B6D11` | 操作成功状态 |
| `--danger` | `#A32D2D` | 表单错误状态 |
| `--info` | `#185FA5` | 信息反馈状态 |

- 用 CSS 变量／设计 Token 归拢分散色值；既有 `--gold` 若实际不是金色，应检查使用位置后逐步重命名或迁移，禁止盲目全局替换。
- 正常正文目标对比度不低于 **4.5:1**，大字号文字不低于 **3:1**；实际搭配必须经过检查。低对比的金色不直接用于小号正文或不可辨认的价格。
- 保留原设计所需的透明度和覆盖层衍生值，优先从变量生成；无需强行禁止所有 `rgba()`、透明背景或组件状态色。

### 2.2 字体与字阶（必须保持现状）

**本次明确不更换字体。** 网站现有的字体家族、字体加载方式、回退顺序，以及标题、正文、按钮、导航、表单和金额的字体配置，均以当前 GitHub 前台实际样式为准；先在代码中核对，不通过本文件推定当前字体的具体名称。

- 不引入 Noto Serif SC／思源宋体或其他新的品牌字体；不增加字体 CDN、自托管字体或字体子集工作。
- 不为了统一视觉而修改全站 `font-family`、字重体系或字体文件；CSS 重构和 Token 迁移应保留现有字体表现。
- 仅允许在**保持现有字体家族与整体文字风格**的条件下微调组件局部字号、行高、字间距、文字截断或对齐，以修复可读性、换行及移动端溢出问题。
- 原有标题层级、字号比例和字重以现状为基准，不强制采用 v1.0 的 H1/H2/H3 推荐值。价格数字可在不更换字体的前提下使用 `font-variant-numeric: tabular-nums`，但须检查是否改变原页面对齐。
- 验收时比较改造前后桌面与手机截图，确认字体外观不变，简体中文字形、导航标签及价格显示正常。

### 2.3 间距、栅格与响应式

- 采用 **8px 基础间距**；图标对齐等细节可使用 4px 微调。
- 内容容器建议 `max-width: 1216px`；保留实际页面的合理宽度与留白，桌面／平板／手机分别检查。
- 页面区块与卡片间距一致化；不为追求统一而改变已有信息顺序。
- 优先复用项目已存在的响应式断点（原版参考：640／960／1100px）；不得未经核对增设大量重复断点。

### 2.4 圆角与阴影

| 元素 | 建议规范 |
|---|---|
| 按钮、输入框、小标签 | 6px |
| 卡片、信息容器 | 10px |
| 大型入口卡 | 16px |
| 一般卡片阴影 | `0 2px 8px rgba(32,38,31,0.06)` |
| 浮层与 hover 阴影 | `0 12px 36px rgba(38,59,45,0.10)`；按需使用 |

### 2.5 微交互与动效

- 按钮及 hover 过渡约 180ms，卡片约 350ms；原则是轻量、不影响阅读。
- 原有动效可保留；不要为了达到固定 700ms 入场时长强制每个区块动画。
- 对 `prefers-reduced-motion: reduce`，取消非必要移动、滚动入场和视差效果。

### 2.6 图标

- 新增或替换的图标采用与现有一致的 **Lucide 风格线性图标**，推荐线宽约 2px，按组件取 15／19／24／27px。
- 同类功能的图标尺寸、线宽和触控区域保持一致；不可为装饰随意新增图标。
- 图标颜色以主色或辅助色为主，必须满足可辨识性。

## 3. 既有组件的视觉与操作优化

### 3.1 按钮与链接

| 类型 | 建议样式 | 范围 |
|---|---|---|
| 主操作 | 黛绿底／白字，圆角 6px | 既有主按钮 |
| 次操作 | 浅底或透明底／深色边框 | 既有次级功能 |
| 文字链接 | 深绿文字／必要时搭配方向箭头 | 返回与查看详情等链接 |

- 保留现有按钮的**文案、数量、目的地和业务行为**；仅调整对比度、间距、状态和尺寸。
- 必须具备 hover、focus-visible、disabled、loading（如现有流程需要）及触控反馈。
- 手机端主要触控目标建议至少 44×44px；不要增加重复 WhatsApp 按钮作为满足尺寸的替代手段。

### 3.2 产品价格视觉

- 金额使用可读的字号（建议约 22–24px，按组件调整）、字重和 `tabular-nums`，颜色以实际对比度检查决定。
- **价格展示模式继续由现有产品需求及真实资料决定**：骨灰位等按现有规则显示 `RM xxx 起`；殡仪服务同时显示**预购价格**和**即用价格**；其他类别显示实际售价或既定多方案显示方式。
- 价格备注文字统一为：**以上价格未包含印花税**。不计算或展示印花税金额，不额外添加日期及税率。
- 不给所有产品强制追加“起”，也不凭视觉需求增加“折扣价”“分期价”等字段。

### 3.3 产品卡片

- 保留既有业务信息与显示顺序：真实图片／占位图、名称、适用人数与宗教标签（仅适用时）、价格、既有详情操作。
- 优化图片比例、留白、标签可读性、价格层级、卡片 hover/focus 状态。
- **不新增每张卡片的「咨询此款」按钮**；不更改整卡与「查看详情」的既有导航规则。
- 不增加库存和前台销售状态字段；不新增楼层、面积或朝向等不适用的骨灰位字段。

### 3.4 图片占位框

在真实图片尚未上架时保留占位方案，统一视觉：

1. 使用简洁的中性占位内容，以类别／产品名称或已有品牌线条表现，不使用误导性的假实景图。
2. 统一参考比例：列表卡片 16:9、详情主图与缩略图 3:2；实际布局应检查是否裁切重要信息。
3. 背景采用 `--surface-tint`，边框采用 `--line` 的细实线；移除大面积虚线或明显的“开发中”视觉样式。
4. 图片暂缺时维持合理的空态，不把无图产品伪装成已有实景；真实图片上传后优先显示实拍素材。
5. 对真实图片优先采用适当压缩与响应式尺寸，不强制所有原图必须同一像素宽度或人为统一色调。

### 3.5 分类筛选与空态

- 保留已确认的七大分类、适用人数导航及宗教筛选规则。
- **不以“产品少于5件”作为强制隐藏搜索和视图切换的规则**；若当前操作无实际作用，可在不改变核心筛选路径的前提下简化呈现，并测试后确认。
- 无产品时显示清晰的空态（如“当前暂无产品资料”），可保留现有分类入口；不强制附加 WhatsApp 操作或“筹备中”标签。

### 3.5.1 七大产品类别 Tab（重点优化）

**范围：仅改善外观、触控和适配，不修改七大类别名称、顺序、分类规则、路由及数据读取逻辑。**

1. 桌面端继续使用现有横向七类导航，保留依次为：**火化土葬、传统土葬、骨灰位、殡仪服务、祖先牌位、生基风水、宠物安葬**。
2. 收紧过高的 Tab、过大的左右空白和文字与下划线之间的距离；以现有布局为基线做局部调整，不强制改成圆角胶囊按钮。
3. 选中态、悬停态及键盘焦点态要有明确区别；当前类别应有足够对比度的背景或底部指示线，视觉变化不能仅靠颜色表达。
4. 手机端优先采用**单行横向滚动的类别 Tab**，不挤成七列、不擅自替换为下拉菜单；当前项切换后须在可视区内，保留可用的滚动提示。
5. 保留原有字体与字号风格，仅在文字溢出或触控区域不足时微调局部尺寸。触控目标建议至少 44×44px。
6. 类别切换后的人数、宗教、产品列表和视图状态仍按现有产品需求执行，不新增分类，不擅自更改筛选重置规则。

### 3.5.2 使用人数与适用宗教筛选

1. 两组控件统一行距、按钮高度、内边距、边框、圆角与选中态；保留当前网站字体，改善标签和选项的视觉对齐。
2. 桌面端将「使用人数」「适用宗教」标签与各自选项排成清楚的行；移动端允许标签与按钮换行，避免文本受挤压、遮挡或出现横向页面溢出。
3. **火化土葬、传统土葬：** 显示人数与宗教筛选；人数可选择全部、单人、双人、家庭。
4. **骨灰位：** 显示安放人数与宗教筛选；人数可选择全部、单人、双人、三人、四人及以上。
5. **殡仪服务：** 只显示宗教筛选，不显示人数筛选。
6. **祖先牌位、生基风水、宠物安葬：** 不显示人数或宗教筛选。
7. 人数默认「全部」，宗教默认「全部宗教」；不得将前台的「全部」值作为后台单件产品的人数字段。
8. 不增加园区、楼层、尺寸、面积、朝向等前台筛选条件，也不改变筛选组合及结果规则。

### 3.5.3 网格／列表视图与筛选入口

1. 保留现有网格／列表切换和筛选入口及其实际业务逻辑；统一图标尺寸、外框、间距、选中态、悬停态和键盘焦点样式。
2. 桌面端与人数／宗教筛选保持清楚的布局关系；手机端可另起一行，按钮不能与筛选内容重叠。
3. 网格与列表切换应保持当前筛选条件，不清空用户选择；不得将视图切换误用作产品排序操作。
4. 搜索或视图切换是否显示，不采用「少于 5 件产品就隐藏」的机械规则，优先保持已有功能可发现；如确需隐藏，须先明确场景并经单独确认。
5. 图标必须具备可访问名称，移动端按钮有足够点击区域；状态不能只靠图标颜色区分。

### 3.5.4 本区域验收标准

- [ ] 七大类别名称、顺序与切换逻辑不变。
- [ ] 桌面端 Tab 高度及留白优化后仍完整可读；手机端可左右滑动访问所有类别。
- [ ] 切换类别、人数、宗教时正确显示对应控件与结果；隐藏不适用控件。
- [ ] 选中、悬停、键盘焦点、触控操作均可辨认。
- [ ] 网格／列表切换与筛选入口正常运行，手机端不重叠。
- [ ] **没有改变现有字体**、没有新增不适用的前台筛选项或业务字段。

### 3.6 联系表单与问卷

- 保留已确认的直接提交和现有 WhatsApp 内容／跳转流程；**不恢复「生成咨询草稿 → 再预览 → 才提交」步骤**。
- 保留现有问卷题目顺序及条件分支；仅改善步骤的可理解性与错误提示，现有进度提示如已具备则优化样式，不擅自新增步骤。
- 输入错误在对应字段附近说明原因；提交成功或失败提供可辨识的反馈，不只依赖颜色或弹窗。
- 不新增未确认的回应时间承诺。

### 3.7 导航、页脚与手机菜单

- 导航选中态可使用少量 `--accent` 强调，但需验证可访问性；不得牺牲辨识度。
- 页脚沿用现有内容结构与深色视觉，只统一字体、链接和间距。
- 手机端菜单保留原交互，并核查打开时的遮罩、关闭操作、焦点管理及滚动状态。
- **不强制全站浮动 WhatsApp 按钮**；已有首屏明确咨询入口时，避免重复遮挡内容。

## 4. 页面级改造范围

### 4.1 首页

- 优化现有富贵山庄与云南善堂入口卡的辨识度：在有真实素材时使用各自合适图片；暂无素材时仅使用中性占位，不要求新增英文眉题。
- 对现有图片上的文字检查亮暗对比，必要时微调遮罩或阴影，避免一刀切使用固定 75% 遮罩。
- 保留现有服务流程、理念与服务入口的内容数量和先后顺序；**不增加独立资质／信任区或热门配套模块**。

### 4.2 富贵山庄产品目录与分类

- 在不改变原有导航与筛选的前提下，调整顶部区域不必要的空白、标题层级和卡片间距。
- 若现有类别尚无已发布产品，统一采用清楚的中性空态；不强行判定“七类中有五类空缺”为长期事实。
- 既有“了解园区”等内容卡仅优化占位图与排列间距，不强制删除到两张。
- 手机端对比表格可横向滚动时，提供不遮挡数据的滚动提示；面包屑及价格文字统一可读性。

### 4.3 产品详情页

- 保留已确认的详情字段、信息顺序、价格展示和已有咨询路径。
- 优化标题、标签、规格表、图片画廊及现有信息区域的层级；已有侧栏则检查布局及移动端堆叠，不强制重建。
- **不增加分期付款、付款比例、额外 CTA、相关推荐或 FAQ 模块**。
- **待核验项目**：检查源码中 `PackageDetail.tsx` 的咨询入口是否在当前部署产物中实际可见；如存在差异，先检查路由、构建、部署分支及条件渲染，再修复确证的问题。

### 4.4 联系页

- 统一联系方式、既有咨询表单及问卷的字体、留白、表单状态和响应式间距。
- 维持既定的直接提交路径，保留既有字段与 WhatsApp 分段内容逻辑；不新增额外流程。
- 保留既有顾问信息，不强制新增头像占位、资质或回应时间承诺。

### 4.5 云南善堂现有前台页面

- 只优化现有页面的视觉一致性、图片占位和响应式表现。
- **不新增云南善堂分类、产品管理数据结构或业务模块**；这与后台的云南善堂占位页是不同范畴，均需以后另行确认需求。

## 5. 内容及文案约束

- **全站简体中文**，保留已确认的正式产品名称与必要行业术语；不得机械删除“墓”等准确产品术语。
- 沿用现有价目表达规则，不将所有价格统一写为“RM xxx 起”。
- 价格备注保持固定文字：**以上价格未包含印花税**。
- 宗教标签与专属设计以实际产品资料为准，不新增未经证实的认证标志、供应承诺、免责声明或付款条款。
- 本次不修改已有电话号码、咨询对象或机构身份信息。

## 6. 可访问性与性能

- 保留并检查语义化 HTML、合理标题层级、skip link（若已使用）、键盘焦点、标签关联与 aria 描述。
- 对比度按 WCAG AA 检查；金色与浅灰色文字尤其需要实测。
- 图片优先使用适当尺寸的 WebP／AVIF（视兼容性），非首屏图片懒加载；首屏重要图片根据实际 LCP 情况设置加载优先级。
- 任何新字体需回退与性能测试，不能以视觉统一为由拖慢首屏。
- 性能目标：LCP 目标不高于 2.5s、CLS 目标低于 0.1；按实际测试设备、连接条件记录结果，不宣称修改前后必然达到。
- 对 `prefers-reduced-motion` 提供无非必要动画的体验。
