## 资料和隔离方式

云端运行标识为 `3e73e8d2`。新建 5 项独立测试产品，名称及编号明确标记 `TEST-PHASE3`；另创建 1 项 AA 副本。测试脚本持有当前运行 ID 白名单，每次修改／删除前检查 ID，清理前再次确认记录为本次前缀且从未发布。未复用原有 20 项产品或其子记录。

来源结构沿用 `supabase/fixtures/real-product-structures.json`，其原文件摘要和价格来源已记录。聚仙楼只验证既有名称及不完整草稿，不采用待审文件中的参考价格、室内／室外字段或自动补齐资料。

云端临时建立管理员、编辑员及普通 Auth 用户各一名，通过正常 Auth 密码登录取得实际 JWT；伪造的用户 metadata 不能赋予管理员权限。临时后台成员仅关联此次测试用户，既有管理员不变。

服务端密钥只暂存本机忽略目录、文件权限 0600。产品读写使用真实用户 JWT 调用正式 RPC；高权限密钥仅用于测试账号管理、正式复制／清理服务，以及清理后的文件不存在检查。没有配置到 `VITE_` 变量或发送到后台网页；实际浏览器产物密钥扫描通过。测试结束删除临时密钥文件和测试凭据文件。

## 发布、隐藏、权限和故障测试

完整“发布 → 匿名公开列表／详情及图片读取 → 修改 → 宗教隐藏 → 隐藏产品 → 旧图访问拒绝”在独立本地真实 Supabase 执行并提交，包含实际 HTTP 和 Storage 字节访问。

云端所有跨请求持久化写入仅限新建非公开草稿。云端发布、公开 RPC 投影、宗教过滤、隐藏、再次发布及曾发布产品删除拒绝在单一实际数据库事务内执行，结束明确 `ROLLBACK`。使用真实上传的对象，不伪造 `storage.objects`。四个案例分别为 W、AA、佛教殡仪及基督教殡仪，聚仙楼通过真实 HTTP 证实资料不完整不能发布。

**云端提交后的公开 HTTP／图片生命周期没有执行，也没有把事务内的数据库角色测试冒充该项测试。** 这样可避免新建测试产品短暂进入现有公开目录；该生命周期已在隔离本地真实栈完整验证。没有以关闭 RLS、临时放宽公开策略或新增测试字段来实现隔离。

其他通过项：

- 云端实际上传、下载 15 个私有对象；匿名及无后台成员用户被拒；受限图片不能签发绕过后续权限检查的签名 URL。
- 实际生产复制 handler 读取源图、上传新私有文件并调用复制事务；副本图片及售价均未公开，源产品保持不变。
- 两个真实云端 HTTP 请求使用同一版本同时保存，一次 200、一次 409。
- 无效多表变更拒绝时，名称、关联价格及原版本均未改变；旧版本复制请求直接返回 409。
- 编辑员可以维护新草稿，不能发布；普通登录用户伪造 metadata 仍无法调用后台接口。
- 本地故障注入覆盖审计失败整笔回滚、复制期间真实并发冲突与文件补偿、实际 Storage 删除失败和重试；没有向云端植入故障触发器或改动云端权限策略。
- 七类独立排序、字典快速新增、响应式、错误回填和表单冲突保留由本地正式后台端到端验证；云端不重排现有产品来测试排序。
